# 首错步骤标注协议（双人独立 + 第三人裁决）

## 1. 为什么需要这份协议

本项目 286 条金标里，16 条来自人工标注，270 条来自**缺陷注入构造**（`source="constructed"`）。
构造式金标的首错步骤与错误类型由注入意图确定，可复现、可审计，但它终究不是"两个人各自看过一遍后的一致意见"。
任务书要求提供**人工抽检记录**，因此本仓库同时提供：

1. 构造式金标的完整 provenance（每条样本都记了 `intended_step` / `intended_type` / `what_changed` / `why_wrong`）；
2. 一份**盲审标注表**（`results/human_audit.csv` 右侧空列），供两名标注者独立填写；
3. 一致性与裁决的计算方法（下文 + `scripts/annotation_agreement.py`）。

**诚实声明**：本仓库有 16 条早期人工单审样本，已整理为 `results/human_spot_check.csv`；其余 270 条构造式金标的定位结论由注入意图给出。286 条尚未完成真人双标注，不能表述为“286 条人工标注金标”。补齐真人标注后，用第 4 节脚本重算一致性并替换报告中的对应数字。

16 条单审结果只用于满足最低人工抽检记录并展示口径：9 条过程错误的首步定位为 9/9，7 条答案与过程均正确的样本误报 0/7，5 条答案正确但被告警的样本均确认存在真实过程问题。由于样本小且与早期规则开发同源，这些数字不得代替 270 条独立构造集的结果。

## 2. 标注对象与盲审要求

对每条样本，标注者会看到：**题面（prompt/signature/constraints）+ 该样本的步骤（steps）+ 该样本的代码**。
标注者**不会**看到：

- 评估器的判定结果（`pred_*` 列）
- 构造时记录的注入意图（`intended_error_type` 列）
- 隐藏测试内容（防止用"测试是否通过"倒推过程是否成立）
- 另一名标注者的结果

盲审的实现方式：由第三方（非标注者）从 `results/human_audit.csv` 中裁掉 `pred_*`、`intended_error_type`、
`gold_*` 三列，另存为盲审表发给标注者；标注完成后再按 `sample_id` 合并回来。

## 3. 标注任务

每题填写三项：

| 字段 | 取值 | 说明 |
|---|---|---|
| `ann{1,2}_step` | `S1`…`Sn` 或 `CODE` 或 `NONE` | 首个使后续结论不再可靠的步骤。`CODE` 表示步骤本身成立但代码实现与步骤不符；`NONE` 表示过程无问题 |
| `ann{1,2}_type` | 10 类之一或 `NONE` | 见 `docs/METHOD.md` 第 4 节的错误体系 |
| `ann{1,2}_is_real_issue` | `Y` / `N` | 该步骤的问题是否**真实存在**（用于区分评估器误报与真实缺陷） |

判定"首错"的操作性定义（避免两人标准漂移）：

> 自 S1 起向后逐步检查。若某一步的主张本身错误、缺少可验证依据、或与题目明确约束冲突，即记为该步为首错并停止。
> 若所有步骤主张均成立，但代码实现与步骤描述不符，记 `CODE`。仅凭"最终答案错误"不得反推过程有错。

## 4. 一致性与裁决

两名标注者独立完成，用 Cohen's kappa 衡量一致性（对 `*_step` 的标称类别计算）：

```bash
PYTHONPATH=src python scripts/annotation_agreement.py results/human_audit.csv
```

脚本输出：标注覆盖率、原始一致率、Cohen's kappa、按错误类型的一致率、以及需要裁决的冲突样本清单。

裁决规则：

1. 两名标注者的 `*_step` 一致 → 直接采纳，无需裁决；
2. `*_step` 相邻（如 S2 vs S3）→ 由第三人裁决，并在 `adjudicator_note` 记录理由；
3. `*_step` 不相邻，或其中一人判 `NONE` → 第三人裁决；
4. `is_real_issue` 不一致 → 以第三人判断为准，该样本计入"误报争议"统计。

冲突样本裁决后写入 `adjudicated_step` / `adjudicated_type`，第三人裁决结果即最终金标。

## 5. 抽检规模建议

全量 286 条双标注成本较高，建议分层抽样：

- 按错误类型分层，每类至少 10 条 → 约 100 条；
- 其中必须包含全部 97 条 `gold_process_correct=true` 样本中的至少 30 条（用于误报率的独立复核）；
- 至少 30 条由两名标注者重复标注同一批（用于计算 kappa，建议 kappa ≥ 0.6 才认为标注可靠）。

## 6. 与评估器指标的对应关系

| 报告指标 | 依赖的标注字段 |
|---|---|
| 定位准确率 | `adjudicated_step` vs `pred_first_error_step` |
| 误报率 | 在 `gold_final_correct=true` 样本中，`ann*_is_real_issue=N` 的占比 |
| 错误类型 F1 | `adjudicated_type` vs `pred_error_type` |

补齐标注后，把构造式金标（`source="constructed"`）与人工标注金标（`source="human"`）**分开报告**，
不要混在一个数字里——二者的可信度不同，混报会掩盖构造式金标的循环性风险。
