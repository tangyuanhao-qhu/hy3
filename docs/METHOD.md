# 过程评估方法

## 1. 评估对象

本项目不要求模型输出私有思维链，而要求输出可供验证的简洁记录：算法方案、关键不变量、必要边界、复杂度和代码对应。每项使用稳定步骤编号 `S1...Sn`，便于人工和程序定位。

## 2. 三类证据

### 结果证据

可见测试用于模型自检，隐藏测试和边界用例用于最终功能判定。最终答案正确定义为隐藏测试全部通过，超时、安全策略失败或任一断言失败均判错。

### 程序证据

AST 安全检查拒绝危险语法。题目级规则识别可明确证明的冲突，例如“两数之和排序后仍保留原下标”“闭区间端点接触不合并”。这些规则可解释、可回归，命中后拥有否决权。

### 语义证据

Hy3 评审器对照题意、约束、步骤、代码和脱敏测试摘要，逐步输出 `valid / invalid / unsupported / skipped`，并定位最早使后续结论不再可靠的步骤。为降低自评偏差，正式实验应将解题和评审请求分开，可进一步用不同采样种子交叉复核。

## 3. 证据融合

1. `forbidden_claims` 命中疑似明确矛盾：记为**强规则候选证据**，定位至首次命中步骤。
2. `required_concepts` 仅发生字面缺词：记为**弱信号**，不得直接否决；有 Hy3 时交给语义复核，没有 Hy3 时保留为待复核告警。
3. 有 Hy3 时，无论强/弱信号都把规则证据一并交给 Hy3 语义复核；规则只在离线模式或 API 失败时作为降级结果。
4. 隐藏测试失败但过程未发现错误：定位为 `CODE / 实现不一致`，表示步骤级解释未覆盖实现缺陷。
5. 隐藏测试全过而过程判错：标记“答案正确但过程不成立”，不把测试通过当成过程正确。

弱信号降级来自实测而非主观选择：run2 的 64 条弱关键词告警中，Hy3 判断 59 条（92.19%）已用其他措辞表达同一含义。进一步抽查还发现 M01 的正则会把“端点接触……不变量”误读成“端点接触不合并”。因此当前实现把所有规则命中都视为可审计候选证据，由 Hy3 做最终语义裁决；只有离线或 API 失败时才返回规则结果。

## 4. 错误体系

| 类型 | 可操作定义 | 代码例子 |
|---|---|---|
| 题意误读 | 优化对象或返回内容理解错误 | 把连续子串当子序列 |
| 概念错误 | 使用的算法/数学事实不成立 | 认为排序保留原下标 |
| 条件遗漏 | 未覆盖题目明确约束或必要分支 | 忽略字符重数 |
| 计算错误 | 正确公式被错误代入或运算 | 状态值加减错误 |
| 跳步推导 | 关键结论缺少可验证依据 | 直接宣称贪心最优 |
| 复杂度错误 | 声称复杂度与实现不符 | 双重循环声称 O(n) |
| 边界错误 | 空输入、重复、端点或下标处理错误 | 二分命中即返回首次位置 |
| 实现不一致 | 步骤成立但代码未实现 | 说明去重，代码未去重 |
| 格式不符 | 输出结构或函数签名不满足协议 | 返回打印文本而非函数值 |
| 幻觉 | 引用不存在的题设、API、定理或测试证据 | 声称题目保证数组有序 |

## 5. 有效性实验

冻结独立金标集后，至少报告：

- `定位准确率 = 首错步骤完全匹配数 / 金标过程错误数`；
- `误报率 = 金标答案及过程均正确但被告警数 / 金标答案及过程均正确数`；
- 错误类型 macro-F1 和混淆矩阵（样本足够后）；
- 两名标注者的步骤定位一致率，冲突样本由第三人裁决；
- 对定位准确率与误报率给出 bootstrap 95% 置信区间。

当前验证集共 286 条：16 条早期人工单审样本和 270 条独立缺陷注入样本。完整集合的规则层定位准确率为 0.249，干净正确样本误报率为 0；独立构造子集定位率为 38/180（0.211），人工单审子集为 9/9，但后者样本小且与早期规则开发同源，必须分开报告。

Hy3 run2 的 90 道模型输出另行评估：最终答案 90/90；原始过程告警 68 条。对 64 条弱信号逐条裁决后，59 条为同义表达、5 条为可能真实遗漏；再用完整 Hy3 judge 复核其余 4 条正则告警，4 条全部清除。最终估计过程问题共 5 条。该校正由 Hy3 完成，不是人工金标，因此报告使用“估计”字样。
