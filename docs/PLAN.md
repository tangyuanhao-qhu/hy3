# 定制实施计划

| 阶段 | 任务 | 可验收输出 | 建议时长 |
|---|---|---|---|
| P0 最小闭环 | 跑通 Hy3 解题、隐藏测试、分步复核、首错输出 | 单题 UI、JSON 结果、Demo 模式 | 已完成 |
| P1 题集扩展 | 扩展至每层 30 题；每题补充可见、隐藏和边界用例 | 90+ 题 JSONL、题源/许可记录 | 3–5 天 |
| P2 对抗过程集 | 每题构造正确、首错、跳步、碰巧通过四类答案 | 180–270 条双人标注金标 | 3–5 天 |
| P3 正式 Hy3 运行 | 固定参数运行至少 3 次，保存原始步骤和代码 | 模型原始输出、逐题评估 JSON | 1–2 天 |
| P4 评估器验证 | 在冻结盲测集上计算定位准确率、误报率和分类混淆 | 指标表、95% bootstrap CI、抽检 CSV | 2 天 |
| P5 临界点分析 | 按难度、边界数、组件数分析首次明显下降区间 | 图表、典型案例、能力边界结论 | 1–2 天 |
| P6 提交包装 | 清理密钥、补许可证、录屏、复现检查 | 开源仓库、报告、2 分钟内视频/GIF | 1 天 |

## 冻结顺序

先冻结题目、隐藏测试和人工金标，再调评估器；否则会发生验证集泄漏。正式结果必须由 `DEMO_MODE=0` 生成，默认烟雾结果只能证明工程链路可运行。

## 最低提交门槛

- 每层至少 30 题，隐藏测试不少于 5 个；
- 每种主要错误类型至少 15 个金标样本；
- 首错标注双人独立完成，一致性和裁决均留记录；
- 同时报告最终答案准确率、过程正确率、定位准确率、误报率；
- 展示至少 3 个“答案正确但过程不成立”案例；
- Demo 不暴露隐藏测试，不执行任意系统调用。
